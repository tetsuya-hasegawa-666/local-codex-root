# writing style governance

## 目的

- shared 文体 rule が更新された時に、`AGENTS.md` と関連文書の表現整合を同じ task で確認する基準とする。

## 中核原則

- 文字数当たりの情報量を最大化する。
- 人が追える可読性を落とさない。
- 誤解のない一意な表現を選ぶ。
- 同じ意味の重複、曖昧語、回りくどい助詞回しを減らす。
- decorative な統一より、truth の誤読防止を優先する。

## 適用対象

- `AGENTS.md`
- `agents.md`
- skill の `SKILL.md`
- shared rule を説明する reference
- 同一 task で追随が必要な履歴文書

## 確認観点

- 同一概念に複数の言い回しが混在していないか
- 長文化しても意味が増えていない文が残っていないか
- 省略しすぎて主語、条件、禁止、例外が曖昧になっていないか
- 箇条書きごとの責務が 1 つに保たれているか
- rule 文が「してよい」「してはならない」「必須」のどれかに正規化できるか

## 優先順

1. source of truth の rule 文
2. skill の責務文
3. routing / trigger reference
4. 履歴文書

## 禁止

- 文体調整だけで rule の意味を変えること
- 上位文書を直さずに下位文書だけ言い換えること
- chat だけに新しい文体 rule を残すこと
